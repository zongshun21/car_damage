# 03 数据集目录与 YOLO 标签格式

## 本章目标

正确组织训练集和验证集，理解每张图片为什么需要一个同名 `.txt` 文件，并能手工读懂一行 YOLO 边界框标签。

输出哈希必须与上面完全相同。哈希不一致通常表示下载不完整或文件版本错误，不要用损坏的压缩包开始训练。

## 2. 目录结构

将合法获得的数据集放在项目根目录，默认名称为 `车损车身数据集`：

```text
车损车身数据集/
├─ train/
│  ├─ images/
│  │  ├─ car001.jpg
│  │  └─ car002.jpg
│  └─ labels/
│     ├─ car001.txt
│     └─ car002.txt
└─ val/
   ├─ images/
   └─ labels/
```

图片和标签通过“主文件名”匹配：`car001.jpg` 对应 `car001.txt`。扩展名可以不同，但主文件名必须完全一致。

压缩包已经包含顶层目录 `车损车身数据集`。将它解压到项目根目录即可，不要再额外套一层同名目录。如果最终变成 `车损车身数据集/车损车身数据集/train`，说明多嵌套了一层。数据使用者需要自行确认数据来源、隐私与授权条件。

## 3. 为什么划分 train 和 val

- `train` 用于更新模型权重。
- `val` 只用于评估模型是否能处理未参与训练的数据。

同一张原图的裁剪版、翻转版或增强版不要同时分散到 train 与 val，否则模型可能已经见过几乎相同的画面，验证指标会虚高。验证集也不要通过复制来平衡类别。

## 4. 一行标签的含义

YOLO 检测标签每个目标占一行，共五个字段：

```text
class_id x_center y_center width height
```

例如：

```text
0 0.500000 0.420000 0.300000 0.180000
```

含义是：类别 0；框中心位于图片宽度 50%、高度 42% 的位置；框宽是图片宽度的 30%，框高是图片高度的 18%。四个坐标已经归一化，通常位于 0 到 1。

如果图片是 1000×500 像素，那么上面这个框对应：

- 中心横坐标：`0.5 × 1000 = 500`
- 中心纵坐标：`0.42 × 500 = 210`
- 框宽：`0.3 × 1000 = 300`
- 框高：`0.18 × 500 = 90`

标签使用中心点和宽高，而不是左上角、右下角坐标。

## 5. 类别编号

原三分类配置 `configs/data.yaml`：

```yaml
names:
  0: dent
  1: crack
  2: scratch
```

因此：

- `0` = 凹陷
- `1` = 裂纹
- `2` = 划痕

两分类派生数据 `configs/data_two_class.yaml` 使用：

```yaml
names:
  0: dent
  1: scratch
```

注意，原来的 scratch 编号 2 必须重新映射为 1。只删除 crack 而不修改 scratch 编号，会让类别编号越界。

## 6. 空标签是什么

`.txt` 文件存在但内容为空，表示图片中没有需要检测的目标，这类图片称为背景样本。合理的背景样本能帮助模型学习“什么时候不应该画框”。

空标签不一定正确。如果图片明显存在缺陷却没有框，它就是漏标，会教模型忽略真正的缺陷。因此必须结合图片人工判断，不能只看文件大小。

## 7. `data.yaml` 如何连接数据

```yaml
path: ../车损车身数据集
train: train/images
val: val/images
```

`path` 是数据集根目录，`train` 和 `val` 相对它定位图片目录。项目脚本会把这些项目相对路径转换成运行时绝对路径，避免 Ultralytics 因当前工作目录不同而找错数据。

如果你使用其他目录，修改 `path` 即可。例如：

```yaml
path: D:/datasets/my_car_damage
```

Windows YAML 路径推荐使用 `/`，可以减少反斜杠转义问题。

## 8. 常见错误

- 标签有 4 个或 6 个字段：格式错误，检测标签必须正好 5 个字段。
- 类别写成 `1.5`：类别必须是整数。
- 宽或高为 0：框没有面积，不能提供有效定位监督。
- 坐标明显大于 1：可能误把像素坐标当成归一化坐标。
- 有图片没有同名标签：脚本会判定为错误。
- 有标签没有同名图片：通常是删除图片后遗留的标签。

## 成功标准
