# 07 模型验证与指标理解

## 本章目标

独立验证训练权重，理解 Precision、Recall、mAP50、mAP50-95 和逐类别指标，不再把“某个框的置信度”误认为整个模型准确率。

## 1. 为什么训练结束后还要验证

训练终端会显示指标，但独立验证可以明确指定权重、数据和输入尺寸，避免拿错运行目录或错误数据。GUI 能画出框，只能证明程序能运行，不能证明模型质量足够好。

## 2. 验证推荐两分类权重

验证仓库内置权重：

```powershell
conda activate car_damage_yolo26
python scripts/validate.py `
  --weights models/YOLO26s_DentScratch_mAP50_73.18.pt `
  --data configs/data_two_class.yaml `
  --device 0 `
  --imgsz 768 `
  --batch 16 `
  --name two_class_validation
```

验证自己训练的权重：

```powershell
python scripts/validate.py `
  --weights runs/car_damage/yolo26s_two_class_768/weights/best.pt `
  --data configs/data_two_class.yaml `
  --device 0 `
  --imgsz 768
```

CPU 设备把 `--device 0` 改成 `--device cpu`，并根据内存把 batch 减小。

## 3. 四个核心指标

### Precision（精确率）

模型画出的框中，有多少是真的。精确率低通常表现为误报多。

```text
Precision = 真阳性 /（真阳性 + 假阳性）
```

### Recall（召回率）

真实缺陷中，有多少被找到。召回率低通常表现为漏检多。

```text
Recall = 真阳性 /（真阳性 + 假阴性）
```

### mAP50

当预测框与真实框的 IoU 至少为 0.50 时，综合不同置信度阈值计算每类 AP，再对类别取平均。它兼顾分类、定位和排序能力。

### mAP50-95

在 IoU 0.50、0.55……0.95 多个严格程度下求平均，比 mAP50 更难，能更严格地反映框的位置是否准确。

## 4. 当前两分类结果

验证集：1,140 张图片、1,837 个目标，不复制验证样本。

| 类别 | Precision | Recall | mAP50 | mAP50-95 |
|---|---:|---:|---:|---:|
| 全部 | 89.15% | 68.66% | **73.18%** | 56.68% |
| dent | 81.6% | 52.1% | 56.9% | 39.1% |
| scratch | 96.7% | 85.3% | 89.4% | 74.3% |

结论：模型对划痕较强，对凹陷仍有明显漏检。整体 mAP50 达到目标不代表两个类别同样可靠。

## 5. 为什么 Precision 高但 Recall 较低

模型较谨慎：一旦画框通常比较正确，但一些真实缺陷没有画出来。降低推理 `conf` 可能找回更多缺陷，也可能增加误报。阈值调整只能改变取舍，不能替代重新训练。

## 6. 混淆矩阵和验证图片

验证输出默认保存在：

```text
runs/car_damage/two_class_validation/
```

重点查看：

- `confusion_matrix.png`：类别之间和背景之间的混淆。
- `PR_curve.png`：精确率与召回率的取舍。
- `F1_curve.png`：不同阈值下的综合表现。
- `val_batch*_pred.jpg`：模型在验证图片上的实际框。

不要只看一个总分。随机查看正确检测、误报和漏检，才能知道下一次该补什么数据。

## 7. `best.pt` 和 `last.pt`

- `best.pt`：训练过程中验证指标最好的轮次，通常用于验证、推理和 GUI。
- `last.pt`：最后完成轮次，主要用于断点续训。

最后一轮不一定最好，因此部署默认选择 `best.pt`。

## 成功标准

验证脚本正常输出 JSON 指标，运行目录中存在曲线和混淆矩阵，并且你能分别解释误报与漏检。下一步进入 [08 图片推理与结果分析](08_图片推理与结果分析.md)。
