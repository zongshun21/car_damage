# 05 两分类数据集处理

## 本章目标

从原始三分类数据生成只包含 dent（凹陷）和 scratch（划痕）的派生数据集，理解为什么不能直接修改原标签，以及类别编号如何重映射。

## 1. 为什么改成两分类

三分类实验中 scratch 表现很好，dent 中等，crack 明显偏低。crack 的问题不仅是数量少，还包括类别边界和框选规则不一致。继续增加训练轮数不能可靠修复错误监督，因此推荐先做质量更可控的两分类模型。

删除一个低质量类别并不是“模型优化技巧”，而是重新定义任务范围。它牺牲裂纹检测能力，换取更可靠的凹陷和划痕识别。真实业务是否允许这样做，必须由任务需求决定。

## 2. 派生而不是修改原数据

本项目永远保留 `车损车身数据集/`，生成结果写到：

```text
.runtime/two_class_dataset/
├─ train/images
├─ train/labels
├─ val/images
└─ val/labels
```

这样做有三个好处：可以随时回到三分类实验；处理规则写错时不会毁掉原始标签；别人能够重新执行脚本验证过程。

## 3. 执行转换

```powershell
conda activate car_damage_yolo26
python scripts/build_two_class_dataset.py
```

等价的显式命令：

```powershell
python scripts/build_two_class_dataset.py `
  --data configs/data.yaml `
  --output .runtime/two_class_dataset
```

脚本会先检查输出目录。如果目录已经包含文件，它会停止而不是覆盖，防止把不同处理结果混在一起。需要重新生成时，请先确认目录内容不再需要，再手工移走旧目录。

## 4. 标签转换规则

原始编号：

```text
0 dent
1 crack
2 scratch
```

派生编号：

```text
0 dent
1 scratch
```

处理逻辑：

- 保留原 class 0，仍写成 0。
- 删除原 class 1 的所有 crack 框。
- 将原 class 2 的 scratch 改写成 1。
- 删除字段数错误、无法解析、类别越界或宽高不大于 0 的框。
- 图片通过 NTFS 硬链接复用；硬链接不可用时自动复制。

只修改标签，不改变图片内容。含有 crack 且没有其他缺陷的图片会变成空标签背景图，这是合理结果。

## 5. 当前转换结果

| 划分 | 图片 | 保留目标 | 空标签 | dent | scratch |
|---|---:|---:|---:|---:|---:|
| train | 4,560 | 6,964 | 90 | 4,843 | 2,121 |
| val | 1,140 | 1,837 | 14 | 1,355 | 482 |

原始 train 中有 2,124 个 scratch 框，其中 3 个零面积框被过滤，所以派生集保留 2,121 个。val 没有零面积警告。

## 6. 转换后再次检查

```powershell
python scripts/check_dataset.py --data configs/data_two_class.yaml
```

预期：

```text
[train] images=4560 labels=4560 objects=6964 empty=90 warnings=0
[val]   images=1140 labels=1140 objects=1837 empty=14 warnings=0
检查结果: PASS
```

如果图片数不是 5,700，先不要训练。检查原始数据是否完整、输出目录是否混入旧文件。

## 7. 配置如何指向派生数据

`configs/data_two_class.yaml`：

```yaml
path: ../.runtime/two_class_dataset
train: train/images
val: val/images
names:
  0: dent
  1: scratch
```

训练脚本会生成 `.runtime/data.resolved.yaml`，把项目相对路径转换成当前机器的绝对路径。这个运行时文件无需提交 Git。
