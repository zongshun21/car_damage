# 兰州石化职业技术大学车辆车身缺陷智能检测平台最终设计

本文件替代早期五页面方案。

## 目标与部署边界

使用 PyQt6 构建仅含“首页概览”和“智能检测”两个页面的 Windows 桌面平台。平台在安装好 Python/Conda 环境的不同 Windows 电脑上运行，不打包 EXE，不上传图片，不写死盘符、用户名或开发电脑路径。

## 页面

### 首页概览

展示学校和平台名称、当前完整模型名、mAP50、Precision、运行设备、累计任务、累计图片、累计缺陷和最近任务。保留简洁的缺陷分布图，不设置独立历史页面。

### 智能检测

支持打开单图或图片文件夹、具名模型选择、导入外部 `.pt`、GPU/CPU/自动设备、置信度、IoU、输入尺寸、开始、停止、检测前后预览、逐图结果、CSV 导出和打开输出目录。实时显示当前图片耗时、平均耗时、FPS、总体进度及总耗时。

## 模型库

内置 `YOLO26s-两分类车损检测` 和 `YOLO26s-三分类车损检测`。模型清单及内置权重使用项目相对路径。外部模型导入后复制到 `models/custom/`。模型缺失或损坏只禁用对应模型，不导致应用退出。检测期间锁定模型选择。

## 可移植路径

- 项目代码和内置模型：相对项目根目录定位。
- 设置与 SQLite 历史：使用 Qt 的 Windows 用户应用数据目录。
- 默认输出：使用 Qt 的用户文档目录下 `CarDamageResults`。
- 自定义输出目录：由用户选择并保存在本机设置中。
- 打开目录：使用 `QDesktopServices`，不直接调用 `os.startfile`。

复制项目到另一台电脑时不携带原电脑的用户设置和历史；内置模型与代码随项目复制。

## 推理和线程

模型服务缓存当前权重，切换模型时才重新加载。文件夹检测在 QThread 中逐张执行并安全取消。设备为 `auto` 时优先 CUDA 0；CUDA 不可用时使用 CPU，自动模式遇到 CUDA 显存异常时对当前图片回退 CPU。损坏图片记录失败后继续下一张。

## 部署入口

- `setup_gui_env.ps1`：创建或更新 Conda 环境并安装项目依赖。
- `check_gui_env.ps1`：检查 Python、PyQt6、Ultralytics、PyTorch、CUDA 和模型文件。
- `start_gui.ps1`：从项目根目录启动平台。

目标电脑流程为复制项目、运行环境脚本、启动平台。

## 测试与完成标准

自动测试覆盖模型注册、模型导入、路径、设置、SQLite、图片扫描、工作线程、两页面启动和取消。运行 GUI 无界面冒烟测试，并用真实两分类权重完成单图推理。最终主窗口只能访问两个页面，模型名称清晰，文件夹检测期间界面不冻结，输出和 CSV 一致。
