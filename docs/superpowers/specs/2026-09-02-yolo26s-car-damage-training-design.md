# YOLO26s 车辆缺陷检测训练项目设计

## 目标

在现有 YOLO 格式数据集上搭建可复现的 YOLO26s 训练、验证和本地批量图片推理项目。项目由用户自行启动正式训练；交付内容包括独立环境配置、数据预检、训练入口、断点续训、验证入口、单图与文件夹推理入口、自动测试和中文使用文档。

## 范围

本阶段包含：

- 使用现有 `车损车身数据集`，不修改原始图片和标签。
- 创建 Ultralytics YOLO 数据配置。
- 创建 Python 3.11 独立环境安装流程。
- 使用 `yolo26s.pt` 预训练权重进行三类目标检测微调。
- 提供训练、恢复训练、验证和图片推理脚本。
- 提供训练前数据检查、错误提示和项目测试。
- 提供中文 README 和本地部署说明。

本阶段不包含：

- 正式执行 150 轮训练。
- 自动修改或重新划分数据集。
- 视频、摄像头或图形界面推理。
- 实例分割和损伤面积估计。

## 数据集

数据集路径为 `车损车身数据集`，已有：

```text
车损车身数据集/
├── train/
│   ├── images/
│   └── labels/
├── val/
│   ├── images/
│   └── labels/
└── classes.txt
```

类别固定为：

- `0`: dent
- `1`: crack
- `2`: scratch

新增 `configs/data.yaml`，使用相对于项目根目录可解析的路径，声明 train、val 和类别名称。脚本在运行时解析配置路径，不依赖启动命令所在目录。

## 方案选择

采用标准 Python 项目，而不是仅提供命令行片段或 Jupyter Notebook。训练、验证和推理使用独立入口，共享配置解析、路径解析和错误处理组件。

建议结构：

```text
car_damage/
├── configs/
│   ├── data.yaml
│   └── train.yaml
├── scripts/
│   ├── check_dataset.py

├── src/
│   └── car_damage/

│       ├── config.py

```

训练输出统一位于 `runs/car_damage/`。正式训练的最佳权重预期位于训练运行目录下的 `weights/best.pt`，最近断点位于 `weights/last.pt`。

## 环境设计

当前系统 Python 3.14 环境未安装 PyTorch/Ultralytics，且用户级 `pip.ini` 含有无法被 pip 正常解析的 BOM。安装脚本应：

1. 创建名为 `car_damage_yolo26` 的 Python 3.11 独立环境。
2. 仅在安装进程中忽略损坏的用户级 pip 配置，不覆盖或删除全局文件。
3. 安装与当前 Windows、NVIDIA 驱动兼容的 PyTorch 和 Ultralytics 版本。
4. 安装项目本身及测试依赖。
5. 验证 Python、PyTorch、CUDA、Ultralytics 和 GPU 可见性。

安装失败时输出可执行的排错信息，不回退到修改系统 Python。

## 训练设计

默认训练配置：

- 模型：`yolo26s.pt`
- 任务：目标检测
- 输入尺寸：640
- epochs：150
- patience：30
- batch：根据可用 GPU 显存自动选择
- device：`0`
- workers：4
- seed：42
- AMP：启用
- pretrained：启用
- 输出项目：`runs/car_damage`

数据已经包含 Roboflow 增强版本，因此进一步增强保持保守：

- 允许水平翻转。
- 禁止垂直翻转。
- 只使用轻微旋转、平移、缩放和颜色扰动。
- 降低 Mosaic 强度。
- 不启用 MixUp。
- 训练末期关闭 Mosaic。

训练入口读取 `configs/train.yaml`，允许命令行覆盖常用参数。启动前依次检查 CUDA、数据配置、图片标签对应关系和标签合法性。检查失败时不进入训练。

## 断点续训

训练入口提供明确的恢复模式：

- 正常启动：加载 `yolo26s.pt`。
- 恢复训练：加载指定的 `last.pt` 并使用 Ultralytics resume 机制。
- 指定断点不存在时立即报错，不自动退回新训练。

## 验证设计

验证脚本要求显式提供权重，默认建议使用 `best.pt`。输出并保存：

- Precision
- Recall
- mAP50
- mAP50-95
- 每类别指标
- 混淆矩阵和验证可视化（由 Ultralytics 生成）

验证结果需要明确关联权重路径、数据配置和运行时间，避免混淆不同训练实验。

## 推理设计

第一版仅支持：

- 单张图片
- 图片目录

推理入口接受：

- 权重路径
- 输入路径
- 置信度阈值
- IoU 阈值
- 推理设备
- 输出目录
- 是否保存 YOLO 文本预测

输入不存在、目录内无支持图片、权重不存在或 CUDA 不可用时给出明确错误。推理结果保存带框图片；可选保存类别、置信度和坐标文本。

## 数据预检

预检脚本不依赖正式训练，至少检查：

- train/val 图片和标签目录存在。
- 图片与标签文件名一一对应。
- 图片可被训练库读取。
- 每行标签有五个字段。
- 类别编号为 0、1、2。
- 坐标为有限数值并满足 Ultralytics 当前容差。
- 非空框宽高大于零。
- 汇总图片数、空标签数、目标数和类别分布。

空标签被报告为背景样本，但不直接判定失败。任何语法错误、非法类别或缺失图片配对都使预检失败。

## 测试与验收

自动测试覆盖：

- 项目根路径和数据路径解析不依赖当前工作目录。
- 默认配置完整且类型正确。
- 命令行覆盖生效。
- 缺失权重和缺失输入产生非零退出码。
- 数据预检在当前数据集上通过。
- `train.py --help`、`validate.py --help`、`predict.py --help` 可运行。
- 在不启动正式训练的模式下，可以加载配置并构造 YOLO26s 训练调用。

验收不要求执行 150 轮训练。若环境允许下载预训练权重，可额外执行仅加载模型和单张推理的冒烟测试；不得以冒烟测试代替正式训练指标。
