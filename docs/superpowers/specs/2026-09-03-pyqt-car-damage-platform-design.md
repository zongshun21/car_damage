# 兰州石化职业技术大学车辆车身缺陷智能检测平台设计

## 1. 项目目标

在现有 YOLO26s 车辆缺陷项目中新增一个 PyQt6 桌面平台，用于选择本地模型、打开单张图片或图片文件夹、批量识别车身缺陷、查看可视化结果、统计检测数据并管理历史任务。

平台面向学校课程设计与本地演示，界面顶部明确展示“兰州石化职业技术大学”和“车辆车身缺陷智能检测平台”。应用完全本地运行，不要求登录，也不上传图片。

## 2. 技术方案

- Python 3.11
- PyQt6：桌面界面
- Ultralytics YOLO：模型加载与推理
- SQLite：任务历史和检测明细
- QSettings：用户设置
- QThread：后台模型加载和批量推理
- CSV：检测报告导出

除 PyQt6 外不增加大型界面依赖。统计图表使用 Qt 绘制，减少安装和打包复杂度。

## 3. 模型库

平台内置两个可选择的模型：

| 显示名称 | 文件名 | 类别 | mAP50 |
|---|---|---|---:|
| YOLO26s-两分类车损检测 | `YOLO26s_DentScratch_mAP50_73.18.pt` | dent、scratch | 73.18% |
| YOLO26s-三分类车损检测 | `YOLO26s_DentCrackScratch_mAP50_53.10.pt` | dent、crack、scratch | 53.10% |

两分类模型为默认推荐模型。模型清单保存显示名称、文件位置、类别、输入尺寸、指标和说明，权重统一放置在项目 `models/` 目录。

模型管理页面支持：

- 下拉选择内置模型和自定义模型。
- 导入外部 `.pt` 权重；默认以文件名作为显示名称。
- 修改自定义模型显示名称和说明。
- 将任意可用模型设为默认模型。
- 从模型库移除自定义模型，但不允许误删两套内置权重。
- 自动扫描 `models/` 中新加入的 `.pt` 文件。
- 切换模型时在后台加载，并显示成功或失败状态。
- 检测期间锁定模型选择，避免同一任务混用权重。

切换模型后，首页模型卡片、检测类别、结果表格、历史记录和 CSV 报告同步使用完整模型名称。类别名称优先从模型权重读取，并显示中文映射：dent 为凹陷、crack 为裂纹、scratch 为划痕；未知类别保留模型原名称。

## 4. 界面设计

主窗口推荐尺寸为 1440×900，最小尺寸为 1180×720。使用深蓝导航栏、科技蓝与青色强调色、白色内容卡片和橙色告警色，字体优先使用微软雅黑。没有官方校徽图片时不仿造校徽，使用学校中文名称和抽象工业科技图形。

### 4.1 框架

- 顶部品牌区：学校名称、平台名称、当前模型和运行设备状态。
- 左侧导航：首页概览、智能检测、检测记录、模型管理、系统设置。
- 右侧内容区：使用堆叠页面切换，窗口缩放时保持布局可用。
- 底部状态栏：模型状态、任务状态、图片进度和简短错误提示。

### 4.2 首页概览

- 当前模型完整名称、任务类别、mAP50、Precision 和权重状态。
- 累计任务数、累计图片数、检测到的缺陷数和最近检测时间。
- 最近任务列表。
- 凹陷、裂纹、划痕累计统计；当前模型不存在的类别显示为不可用，而不是零检测。

### 4.3 智能检测

- 打开单张图片、选择图片文件夹和清空任务。
- 文件夹扫描支持 jpg、jpeg、png、bmp、webp、tif 和 tiff，不递归扫描子目录。
- 左侧显示待检测图片缩略图和每张图片状态。
- 中间提供原图与检测结果切换，也支持适应窗口缩放。
- 右侧显示当前图片的缺陷列表、类别、置信度和边界框数量。
- 提供模型选择、设备、置信度、IoU 和输入尺寸设置。
- 提供开始、停止和打开输出目录按钮。
- 批量检测期间显示当前文件、完成数量、总数量、百分比和耗时。
- 完成后显示缺陷图片比例、各类别目标数、平均置信度和总耗时。
- 支持导出当前任务 CSV。

### 4.4 检测记录

- 按时间倒序展示任务名称、模型名称、输入目录、图片数、缺陷数、耗时和输出目录。
- 支持搜索、按模型过滤、查看任务明细、打开输出目录、导出 CSV 和删除历史记录。
- 删除历史只删除 SQLite 记录，不自动删除用户图片或检测输出文件。

### 4.5 模型管理

- 以卡片或表格显示完整模型名、类别数、指标、文件大小、路径和可用状态。
- 支持导入、重命名、自定义说明、设为默认和移除自定义模型。
- 内置模型缺失时显示明确提示，并禁止选择，不让应用直接崩溃。

### 4.6 系统设置

- 默认模型、设备自动选择、默认输出目录、置信度、IoU 和输入尺寸。
- GPU 可用时优先 CUDA 0，否则自动回退 CPU。
- 提供恢复默认设置和检测运行环境按钮。

## 5. 代码结构

```text
scripts/gui.py                         # GUI 启动入口
src/car_damage/gui/
├── app.py                             # QApplication 初始化
├── main_window.py                     # 主窗口与页面导航
├── theme.py                           # 颜色、字体和全局 QSS
├── models.py                          # 界面数据对象
├── model_registry.py                  # 模型清单、扫描与导入
├── inference.py                       # YOLO 加载与推理服务
├── workers.py                         # QThread 工作对象与信号
├── history.py                         # SQLite 数据访问
├── settings.py                        # QSettings 封装
├── widgets.py                         # 指标卡、图片视图、统计组件
└── pages/
    ├── dashboard.py
    ├── detection.py
    ├── history_page.py
    ├── model_page.py
    └── settings_page.py
models/
├── models.json                        # 内置和自定义模型元数据
├── YOLO26s_DentScratch_mAP50_73.18.pt
└── YOLO26s_DentCrackScratch_mAP50_53.10.pt
start_gui.ps1                          # 一键启动
```

模块边界如下：界面页面只负责展示与用户操作；`model_registry` 管理模型元数据；`inference` 负责 YOLO；`workers` 负责跨线程执行与取消；`history` 负责持久化。页面不直接访问 YOLO 或拼写 SQL。

## 6. 数据流

1. 应用启动并读取设置、模型清单和历史统计。
2. 模型库验证权重文件，默认模型在后台加载。
3. 用户选择图片或文件夹，应用验证格式并生成待处理列表。
4. 用户开始检测后，界面冻结会影响一致性的设置并创建后台任务。
5. 推理线程逐张返回进度、检测框、置信度、处理耗时和渲染结果路径。
6. 界面实时更新缩略图、主预览、结果表格和统计卡片。
7. 任务正常完成或用户停止后，将已完成部分作为一条历史任务写入 SQLite。
8. 用户可打开输出目录或导出 CSV。

每次任务输出到 `runs/car_damage/gui/<日期时间_模型简称>/`，避免覆盖历史结果。

## 7. 错误处理

- 模型文件不存在、损坏或类别读取失败：显示对话框并保持界面可操作。
- 文件夹为空或包含不支持格式：不启动任务，给出中文提示。
- CUDA 不可用或显存不足：自动尝试 CPU，并在状态栏明确说明。
- 单张图片损坏：记录该图片失败并继续处理其他图片。
- 用户停止：在当前图片完成后安全退出，不强制终止 Python 线程。
- 输出目录不可写或数据库异常：展示错误，不覆盖源图片。
- 应用关闭时如有任务运行，先请求停止并等待工作线程退出。

## 8. 测试与验收

自动测试在 `QT_QPA_PLATFORM=offscreen` 下运行，覆盖：

- 模型清单读取、自动扫描、导入和内置模型保护。
- 图片文件夹扫描、格式过滤与空目录错误。
- 设置默认值、保存与恢复。
- SQLite 任务和检测明细的创建、查询及删除。
- 后台工作对象的进度、成功、失败和取消信号。
- 主窗口和各页面的无界面显示启动。
- 使用真实两分类最佳权重完成单张图片推理冒烟测试。

人工验收包括：打开验证图片文件夹、选择两分类模型、完成批量检测、查看结果、切换历史记录、导出 CSV、切换三分类模型并再次检测。

## 9. 完成标准

- `start_gui.ps1` 能在现有 `dl` 环境启动平台。
- 两套 YOLO26s 模型名称、指标和类别显示正确且可切换。
- 单图和文件夹批量检测均可完成，界面推理期间不冻结。
- 检测图片、表格、统计、历史和 CSV 内容一致。
- 不修改原始数据集和现有训练权重。
- 全部自动测试通过，并完成至少一次真实模型 GUI 推理链路验证。
