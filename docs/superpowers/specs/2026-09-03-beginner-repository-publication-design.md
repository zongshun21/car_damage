# 车辆车身缺陷检测：新手型工程仓库发布设计

## 1. 目标

将当前车辆车身缺陷检测工程整理并发布到 `zongshun21/car_damage` 的 `main` 分支。仓库主要面向没有深度学习基础、第一次接触 YOLO 和 PyQt6 的读者。读者应当能够：

1. 理解项目解决的问题和完整工作流。
2. 在 Windows 电脑上安装 CPU 或 NVIDIA GPU 训练环境。
3. 正确放置自己的数据集并理解 YOLO 标签格式。
4. 检查数据质量，理解为什么需要处理低质量类别。
5. 从三分类数据生成两分类派生数据集。
6. 训练、续训、验证并选择 YOLO26s 最佳权重。
7. 使用权重完成命令行推理。
8. 理解模型如何注册和封装到 PyQt6 GUI。
9. 在另一台 Windows 设备上安装并运行 GUI。
10. 根据错误提示完成基础排障。

## 2. 发布范围

### 2.1 纳入仓库

- Python 源代码、PowerShell 启动脚本和项目配置。
- 数据检查、两分类处理、训练、验证、推理和 GUI 入口脚本。
- 自动化测试。
- 模型注册清单和权重放置说明。
- 项目实验结果、设计记录和面向新手的分章教程。
- GUI 平台截图和中文检测结果示例。
- GUI 直接运行所需的两套已验证权重字节分块、自动还原脚本及其 SHA-256。还原后的 `.pt` 与本地成品逐字节一致。
- 可复现环境声明：`environment.yml`、`pyproject.toml` 和安装脚本。

### 2.2 不纳入仓库

- `车损车身数据集/`：约 168.5 MB，不直接放入 Git；通过带 SHA256 的百度网盘压缩包分发，同时提醒读者确认数据许可，也允许替换成自己的同格式数据集。
- `runs/`：约 2.36 GB，是训练和验证生成物，可通过文档中的命令重新生成。
- `.runtime/`、`.venv*`：与具体机器绑定，无法作为可移植环境发布。
- `release/`：本地部署压缩包的重复副本。
- `__pycache__/`、`.pytest_cache/` 和 `*.egg-info/`：缓存或安装生成物。
- 除两套已验证 GUI 权重之外的 `*.pt`、`*.onnx`：训练过程会产生大量权重，不应重复提交。

不上传上述文件不会降低工程完整性：仓库保存“如何生成结果”的代码、参数和说明，而不是保存某台机器上的环境与全部中间产物。

## 3. 读者学习路线

主 README 只承担导航、项目概览、最短运行路径和关键结果展示。详细教学拆分为以下章节：

1. `01_深度学习与目标检测入门.md`：解释训练、推理、类别、边界框、权重和 epoch。
2. `02_环境安装与GPU检查.md`：介绍 Conda、Python、PyTorch、CUDA 以及 CPU/GPU 两套安装路线。
3. `03_数据集目录与YOLO标签格式.md`：解释图片与标签一一对应、类别编号和归一化坐标。
4. `04_数据检查与清洗.md`：说明漏标、空标签、非法框、重复样本及其影响。
5. `05_两分类数据集处理.md`：说明删除低质量 crack 类的原因、编号重映射和派生数据集原则。
6. `06_YOLO26s模型训练.md`：解释预训练权重、超参数、训练命令、断点续训和输出目录。
7. `07_模型验证与指标理解.md`：解释 Precision、Recall、mAP50 和 mAP50-95，给出本项目结果。
8. `08_图片推理与结果分析.md`：讲解单图、文件夹、CPU/GPU 推理及置信度阈值。
9. `09_GUI平台原理与封装.md`：解释模型注册、后台线程、图像显示、中文标注和历史统计。
10. `10_GUI安装运行与迁移.md`：说明另一台 Windows 电脑的环境安装、权重导入和启动步骤。
11. `11_常见错误排查.md`：按症状整理 CUDA、路径、依赖、权重、标签和 SSH GUI 问题。
12. `12_实验结果与改进建议.md`：记录三分类与两分类对比、限制和后续改进方向。

## 4. 每章写作规范

每个实际操作章节必须包含：

- 本章目标。
- 为什么需要这一步。
- 前置条件和输入文件。
- 可以直接复制的 Windows PowerShell 命令。
- 关键参数逐项解释。
- 正常输出和生成文件的位置。
- 成功判定标准。
- 常见错误、原因和解决办法。
- 与下一步骤的数据流关系。

首次出现的专业术语先用一句通俗语言解释，再给出英文缩写。命令中的项目路径不得写死为作者电脑的绝对路径。涉及耗时和性能时明确说明其取决于硬件，不能把 RTX 4090 的结果承诺为所有电脑的结果。

## 5. 工程数据流

```text
原始图片和 YOLO 标签
        ↓
数据集结构与标签合法性检查
        ↓
类别质量分析与人工复核
        ↓
生成两分类派生数据集（保留原始数据）
        ↓
读取 data.yaml 和 train.yaml
        ↓
加载 YOLO26s 预训练权重
        ↓
训练并生成 last.pt / best.pt
        ↓
独立验证并解释 P、R、mAP50、mAP50-95
        ↓
命令行图片推理
        ↓
将 best.pt 注册或导入 GUI
        ↓
PyQt6 后台线程推理、中文标注、结果导出
```

文档必须解释每个箭头为什么存在。例如，独立验证用于确认模型对未参与参数更新的数据是否具有泛化能力；GUI 封装放在训练和验证之后，是因为界面只负责调用已经可用的模型，不能替代模型质量验证。

## 6. README 设计

README 自上而下包含：

1. 中文项目名称、适用对象和一句话介绍。
2. GUI 截图与中文检测结果。
3. 当前推荐两分类模型的真实验证指标。
4. 功能列表和技术栈。
5. 项目目录树。
6. 两条入口路线：只运行 GUI、从数据开始完整训练。
7. 十分钟快速开始。
8. 详细教程导航表。
9. 数据集不随 Git 分发、模型权重采用分块分发并自动还原的说明。
10. 测试、隐私、本地推理和已知限制。

README 不重复十二章的全部内容，而是保证新手知道“现在该读哪一章”。

## 7. 模型与 GUI 的衔接

仓库在 `models/weights_parts/` 中提供两套 GUI 内置权重的完整字节分块，由 `restore_models.ps1` 自动还原，同时支持读者替换为自己训练的模型：

- 完整复现路线：训练后使用 `runs/.../weights/best.pt`。
- 直接体验路线：克隆后使用仓库中两分类或三分类内置权重。
- 自定义路线：将其他 `.pt` 文件放入 `models/`，或在 GUI 中点击“导入模型”。

文档解释 `models.json` 只是模型元数据清单，`.pt` 才是网络参数。GUI 通过模型注册表查找权重，推理服务加载 YOLO 模型，工作线程逐图预测，主线程只负责刷新界面，从而避免窗口卡死。检测框使用 Pillow 和 Windows 中文字体绘制，内部英文类别会映射为“凹陷、划痕、裂纹”。

## 8. 发布策略

- 目标仓库：`zongshun21/car_damage`。
- 目标分支：`main`。
- 保留现有历史，不使用强制更新。
- 在本地完成文件筛选、文档链接检查和测试后，通过 GitHub Git Data API 创建一次原子提交。
- 提交前读取远程 `main` 最新提交；只有在它仍是本次准备工作的基线时才移动分支，避免覆盖并发修改。
- 提交后重新读取 README 和目录树，并核对远程提交 SHA。

## 9. 验证与验收

发布前必须完成：

1. 运行全部自动化测试。
2. 运行 GUI 离屏启动测试。
3. 检查所有 Markdown 相对链接指向存在的文件。
4. 检查文档中不存在作者机器的绝对路径、密钥、账号令牌和缓存目录。
5. 检查 `.gitignore` 覆盖数据集、权重、环境、训练输出和发布包。
6. 检查教程命令与脚本现有参数一致。
7. 检查远程仓库关键文件内容与本地发布清单一致。

验收标准是：一位只了解基本 Windows 文件操作的新手，可以按照 README 的顺序完成环境检查、数据准备、训练、验证、推理和 GUI 运行，并能理解每个阶段的目的、输入、输出和成功标准。

## 10. 边界与风险

- 数据集来源与许可需要仓库使用者自行确认，文档不宣称拥有第三方图片版权。
- 本项目指标只适用于当前验证集，不代表所有真实车辆场景的准确率。
- crack 类因标签质量不足被排除出推荐模型，但三分类实验结果仍保留在研究记录中。
- CPU 可以运行训练和 GUI，但训练耗时会显著长于 NVIDIA GPU。
- Ultralytics、PyTorch 和驱动版本会随时间变化；仓库固定已验证版本，并说明升级前应重新测试。
