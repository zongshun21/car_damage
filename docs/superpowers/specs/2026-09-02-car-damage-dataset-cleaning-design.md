# 车辆车身缺陷数据集清洗设计

## 目标

在不修改原始数据集 `车损车身数据集` 的前提下，生成可用于车辆车身缺陷目标检测训练的 `车损车身数据集_clean`。清洗结果需要消除同源增强图片跨数据集划分造成的数据泄漏，修复确定性的标注问题，并将无法可靠判断的样本隔离到人工复核区。

## 输入与已知问题

输入数据位于 `车损车身数据集`，采用 YOLO 检测标注，类别映射为：

- `0`: dent（凹陷、鼓包或钣金形变）
- `1`: crack（材料真实开裂或断裂）
- `2`: scratch（真实漆面擦伤或刮痕）

已确认的问题：

- 数据包含 4,560 张训练图片和 1,140 张验证图片。
- 图片文件名含 `.rf.<hash>`，同一源图的增强版本大量跨越 train/val。
- 667 个源图组跨越现有 train/val，影响 893 张验证图片。
- 6 个空标签文件对应的图片仍有明显车损。
- 这些空标签样本的同源版本存在已有标注，其中部分标签类别互相冲突。
- 一些人工画圈、X 或记号笔线被标为 scratch。
- 部分边界框轻微超出归一化坐标范围。
- 当前没有独立测试集，也没有可直接训练所需的 `data.yaml`。

## 安全原则

- 原始数据集只读，不覆盖、不移动、不重命名原文件。
- 所有结果写入新目录 `车损车身数据集_clean`。
- 自动处理仅用于确定性修复；语义不明确的样本进入 `review`。
- 人工画线、粉笔线、文字和标记本身不作为 scratch。
- 每项标签修改都记录原始值、修改后值、原因和源图组。
- 处理失败时不把不完整目录标记为可训练结果。

## 源图分组

以移除文件名末尾 `.rf.<32位十六进制哈希>` 后的名称作为初始源图组键。同组的所有图片和标签始终进入同一个数据划分。

该键只能识别 Roboflow 增强关系。若文件名或元数据能够识别同一车辆、同一次查勘或连续拍摄序列，还应进一步合并为更高层的车辆/拍摄组，避免不同文件名的近重复照片跨集合。

## 六张漏标图片与同源标签修正

对六张空标签图片逐张检查，并同时审查其全部同源版本：

1. 若同源图片几何内容一致、已有框语义正确，则迁移并验证已有框。
2. 若同源图片经过裁剪、翻转或其他几何变换，则根据当前图片重新定位，不直接复制坐标。
3. 若同源标签在 dent/scratch/crack 之间冲突，则以可见的真实物理缺陷为准，统一该源图组。
4. 拼图样本的每个子图分别标注可确认的缺陷，不用一个大框覆盖互不相关的子图。
5. 严重复合损伤允许多个缺陷框；只有真实开裂才使用 crack。
6. 无法区分反光、阴影、污渍和浅损伤的区域不强制标注，样本进入 `review`。

修改后为这六张图片生成带框预览，并保存修正前后对照。

## 坐标与标签校验

每行标签必须符合：

```text
class_id x_center y_center width height
```

校验规则：

- `class_id` 只能为 0、1、2。
- 坐标必须为有限数值。
- 宽和高必须大于零。
- 框边界裁剪到 `[0, 1]`，再重新计算中心点和宽高。
- 裁剪后为零面积的框不静默删除，复制到 `review` 并记录错误。
- 图片与标签文件必须一一对应。
- 允许存在真正的无缺陷负样本，但必须在报告中与漏标样本区分。

## 数据划分

使用固定随机种子，按源图组进行近似分层划分：

- train: 80%
- val: 10%
- test: 10%

划分同时尽量保持三类的源图数量和目标框数量比例。任何源图组不得跨集合。

训练集可以保留同组增强版本。验证集和测试集优先保留每组中最自然、增强最少且标注可靠的代表图片，避免使用大量同源增强副本评估泛化能力。

## 审计与失败条件

处理完成后执行以下验收：

- 图片可正常解码。
- 图片与标签一一对应。
- 所有标签行字段数量、类别和数值合法。
- 所有边界框位于图像内且面积大于零。
- train/val/test 不存在相同源图组。
- train/val/test 不存在相同文件哈希。
- 统计各集合的图片数、源图数、目标数和类别分布。
- 单独统计小目标、空标签、修改标签和隔离样本。
- 为每个类别和每个集合生成随机带框预览。
- 为六张漏标图片生成修正前后预览。

只要存在非法标签、缺失配对、跨集合源图泄漏或跨集合完全重复图片，验收即失败，不将结果声明为可训练版本。

## 实施边界

本阶段负责数据清洗、重新划分、六张漏标图及其同源组修正、训练配置和审计报告，不包含模型训练、依赖安装或推理程序开发。清洗验收通过后，再单独设计 YOLO26n/YOLO26s 的训练与部署流程。
