# 09 GUI 平台原理与封装

本章解释训练得到的 `.pt` 权重如何变成普通用户可以操作的 Windows 桌面程序。理解这些模块后，你既能修改界面，也能替换自己的模型。

## 1. 为什么还需要 GUI

命令行适合训练和调试，但展示项目时通常需要一个更直观的入口。GUI 做了四件事：选择模型和图片、调用模型推理、把框和中文类别画回图片、保存图片与 CSV 结果。它不改变模型精度，只是把推理流程封装起来。

## 2. 程序调用关系

```text
scripts/gui.py
  └─ bootstrap.py：准备 Qt/Windows 启动环境并记录日志
      └─ app.py：创建 QApplication 和主窗口
          └─ main_window.py：组织“首页概览、智能检测”两个页面
              ├─ model_registry.py：读取 models/models.json，管理权重
              ├─ workers.py：在后台线程执行批量检测
              ├─ inference.py：加载 YOLO、推理、中文绘图
              └─ history.py：保存本机检测历史和统计
```

入口文件很薄是有意的：界面、模型、推理和数据持久化各自独立，更容易测试，也更方便将来改成 Web 或服务端界面。

## 3. 为什么使用后台线程

Qt 的主线程负责绘制窗口和响应鼠标。如果直接在主线程加载模型或处理几十张图片，窗口就会显示“未响应”。`InferenceWorker` 在 `QThread` 中工作，通过 Qt 信号把进度、当前结果和错误传回主窗口，因此检测期间界面仍可移动，也可以点击停止。

线程只解决界面卡顿，不会自动提高推理速度。速度主要取决于显卡、输入尺寸、权重大小和首次 CUDA 预热。

## 4. 模型清单与权重

`models/models.json` 是模型清单，`.pt` 是真正的模型参数。每条记录包括：

- `id`：程序内部唯一标识；
- `display_name`：下拉框中显示的名称，不显示精度；
- `filename`：相对 `models/` 的路径，便于换电脑和盘符；
- `classes`：类别顺序，必须与训练时一致；
- `imgsz`：推荐输入尺寸；
- `builtin`：是否为内置模型。

仓库包含两份可选权重。默认推荐两分类模型；三分类模型用于复现实验或仍需识别裂纹的场景。界面也支持“导入模型”，导入后的文件放入 `models/custom/`。

## 5. 单窗口图片交互

智能检测页面只保留一个主要预览窗口：

1. 载入图片时显示原图；
2. 点击“缺陷检测”后，同一窗口切换为带框结果图；
3. 点击任务列表中的图片，可查看对应结果；
4. 下方表格显示类别、置信度和边界框坐标。

这种设计避免在窄屏上并排挤压两张图。预览控件会保持原始宽高比缩放，不会拉伸图片。

## 6. 中文类别如何实现

模型内部类别仍采用 `dent`、`crack`、`scratch`，这样与训练数据和 Ultralytics 保持一致。显示阶段再映射为：

| 模型类别 | 界面中文 |
|---|---|
| dent | 凹陷 |
| crack | 裂纹 |
| scratch | 划痕 |

中文不能可靠地由 OpenCV 默认字体直接绘制，因此推理模块使用 Pillow 和 Windows 中文字体绘制标签。只改显示文字不会改变类别编号；不要在未同步训练标签的情况下交换类别顺序。

## 7. 数据保存在什么地方

- 内置和导入模型：项目目录的 `models/`；
- 检测结果：默认在当前用户“文档/CarDamageResults”；
- 设置、历史数据库和启动日志：`%LOCALAPPDATA%\LZPU\CarDamagePlatform`；
- CSV：由用户选择保存位置。

历史数据只保存在本机，不上传网络。首页的统计可以清零；清零只删除本地历史记录，不删除模型和检测图片。

## 8. 修改或扩展平台

常见修改位置如下：

- 改颜色、圆角和字体：`src/car_damage/gui/theme.py`；
- 改两页内容与布局：`src/car_damage/gui/pages/`；
- 改主窗口、菜单和状态栏：`main_window.py`；
- 改推理阈值或中文绘图：`inference.py`；
- 增加模型：优先使用 GUI 的“导入模型”，或编辑 `models.json`。

修改后先运行 `pytest -q`，再运行 `python scripts/gui.py --smoke-test`。这两个检查分别覆盖业务逻辑和窗口能否创建。
