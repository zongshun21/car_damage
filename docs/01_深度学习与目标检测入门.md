# 01 深度学习与目标检测入门

## 本章目标

这一章不写公式，先建立完整概念。读完后，你应该知道项目为什么需要数据集、标签、模型训练、验证和推理，也能理解终端里常见的 `epoch`、`batch`、`confidence` 等词。

## 1. 我们到底在训练什么

普通程序由开发者明确写规则，例如“像素是红色就判断为划痕”。真实车辆图片受到光照、角度、颜色和背景影响，靠固定规则很难覆盖。深度学习的做法是给模型大量“图片 + 正确答案”，让模型自己调整内部参数，逐渐学会缺陷的外观规律。

本项目属于目标检测（Object Detection），它需要同时回答两个问题：

1. 图片中有没有缺陷，缺陷属于哪一类。
2. 缺陷在图片中的什么位置。

因此训练标签不仅有类别，还有矩形边界框。分类任务只回答“这是什么”，检测任务还要回答“它在哪里”。

## 2. 数据、模型和权重

- **数据集（Dataset）**：用于学习和评估的图片与标签集合。
- **模型结构（Model Architecture）**：神经网络由哪些层组成。本项目使用 YOLO26s。
- **权重（Weights）**：模型学习到的参数，保存在 `.pt` 文件中。
- **预训练权重（Pretrained Weights）**：先在大型通用数据集上学过的起点，例如 `yolo26s.pt`。
- **自定义权重**：在车辆缺陷数据上继续学习后得到的 `best.pt`。

可以把模型结构理解成一套可调节的机器，权重是机器上大量旋钮的最终位置。只复制代码但没有权重，仍然不能得到已经训练好的检测能力。

## 3. 训练、验证和推理

### 训练（Train）

模型查看训练图片，产生预测，与标签答案比较，计算误差，再根据误差更新权重。这个过程重复很多轮。

### 验证（Validation）

验证集不参与权重更新。它用于检查模型面对“没有拿来学习的图片”时表现如何。如果训练成绩很好、验证成绩很差，通常发生了过拟合：模型记住了训练样本，却没有学会可推广的规律。

### 推理（Predict/Inference）

训练完成后，把一张新图片交给模型并得到缺陷框、类别和置信度，这叫推理。GUI 的核心作用就是让用户更方便地选择图片和调用推理。

## 4. 常见训练参数

| 参数 | 通俗解释 | 调大后的典型影响 |
|---|---|---|
| `epochs` | 整个训练集被学习多少轮 | 训练更久，也可能过拟合 |
| `batch` | 一次送入显卡的图片数 | 速度可能提高，但更占显存 |
| `imgsz` | 模型输入边长 | 小缺陷更清晰，但更慢、更占显存 |
| `lr0` | 初始学习率 | 更新更激进，过大可能不收敛 |
| `patience` | 指标多久不改善就早停 | 大一些允许模型等待更久 |
| `device` | 使用 GPU 还是 CPU | GPU 通常快很多 |
| `workers` | 后台读取数据的进程数 | Windows 出问题时可设为 0 |

一个 epoch 不是“一张图”，而是模型完成一次整个训练集的学习。一个 batch 也不是训练总量，只是一次参数更新使用的小批图片。

## 5. 推理参数

- `conf`：置信度阈值。低于阈值的预测会被丢弃。提高它通常减少误报，也可能增加漏检。
- `iou`：非极大值抑制使用的重叠阈值，主要处理多个框重复覆盖同一目标的问题。
- `imgsz`：推理输入尺寸，应尽量与验证时保持一致。本项目推荐 768。

置信度 0.9 表示模型对这次预测很有把握，不表示它在所有图片上有 90% 的准确率。单个框置信度和整个验证集的 mAP 是不同概念。

## 6. 为什么选择 YOLO26s

YOLO 系列将检测过程组织得很紧凑，适合实时或接近实时推理。`s` 表示 small，在精度、速度、显存占用之间较平衡，适合训练后放到普通 Windows 笔记本运行。更大的模型不一定解决错误标签问题，反而会让部署更慢。

本项目使用 Ultralytics Python API，并用自己的脚本封装数据检查、路径解析和异常提示。官方训练、验证和预测模式可参考 [Ultralytics YOLO Modes](https://docs.ultralytics.com/modes/)。

## 7. 本项目完整流程

```text
准备数据 → 检查标签 → 生成两分类数据 → 训练 → 验证 → 推理 → 接入 GUI
```

顺序不能随意颠倒。数据错误会进入训练；训练错误会进入权重；未经验证的权重直接接入 GUI，只会把问题包装得更漂亮。
