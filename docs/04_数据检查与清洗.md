# 04 数据检查与清洗

## 本章目标

在训练前自动发现目录、图片和标签问题，并理解为什么“脚本显示 PASS”仍然不能替代人工观察。

## 1. 为什么训练前必须检查

训练时间可能从几十分钟到数天。如果标签编号错误、图片打不开或图片与标签错配，轻则模型精度下降，重则训练中途失败。先检查几分钟，可以避免浪费大量时间。

自动检查擅长发现格式错误；人工检查擅长发现语义错误。例如，脚本能判断坐标是否越界，却不知道一个框到底圈的是裂纹还是车门接缝。

## 2. 运行检查

```powershell
conda activate car_damage_yolo26
python scripts/check_dataset.py
```

指定其他配置：

```powershell
python scripts/check_dataset.py --data configs/data_two_class.yaml
```

保存机器可读的 JSON 报告：

```powershell
python scripts/check_dataset.py --json runs/dataset_report.json
```

只检查标签、不逐张解码图片：

```powershell
python scripts/check_dataset.py --skip-image-verify
```

最后一种更快，但不能发现损坏图片，正式训练前至少完整检查一次。

## 3. 脚本检查哪些内容

- train/val 图片目录和 labels 目录是否存在。
- 图片与标签的主文件名是否一一对应。
- Pillow 能否读取每张图片。
- 标签每行是否正好有 5 个字段。
- 类别编号是否是整数并位于配置范围内。
- 坐标是否为有限数字、是否超出 Ultralytics 容差。
- 边界框宽高是否大于 0。
- 每个类别有多少目标，以及有多少空标签。

检测到 error 时整体结果为失败；warning 表示仍可加载，但需要关注质量。

## 4. 当前原始数据统计

| 划分 | 图片 | 标签 | 目标总数 | 空标签 | dent | crack | scratch |
|---|---:|---:|---:|---:|---:|---:|---:|
| train | 4,560 | 4,560 | 7,731 | 5 | 4,843 | 764 | 2,124 |
| val | 1,140 | 1,140 | 2,043 | 1 | 1,355 | 206 | 482 |

训练集有 3 个零面积框警告。它们能被当前 Ultralytics 版本读取，但不会提供有效的定位信息；两分类派生脚本会过滤这些框。

## 5. 如何理解类别不平衡

训练集中 dent 有 4,843 个框，crack 只有 764 个框。数量少意味着模型看到裂纹的机会少，但简单复制少数类也不是万能办法：如果原标签本身不一致，复制只会重复错误。

本项目实际复核发现 crack 还存在以下问题：

- 一条裂纹被切成多个很小的框。
- 车身接缝、破损和裂纹的边界不统一。
- 清晰正样本不足。

这解释了三分类模型 crack mAP50 只有 13.6%。最终推荐模型选择 dent 与 scratch 两类，详细原因见第 12 章。

## 6. 人工复核建议

从每个类别随机抽取至少 50–100 张图，检查：

1. 框是否完整覆盖缺陷，而不是只覆盖一小段。
2. 同类缺陷的框法是否一致。
3. 类别是否标错。
4. 明显缺陷是否漏标。
5. train 与 val 是否存在同源重复图。
6. 背景图是否真的没有目标。

不要为了提高数字偷偷修改验证集答案。发现验证标签错误可以修正，但必须记录规则，并重新评估所有相关样本。

## 7. 如何判断成功

输出最后显示 `检查结果: PASS`，并且你已经阅读全部 warning。PASS 只表示数据可以进入训练，不保证标注语义一定高质量。

下一步阅读 [05 两分类数据集处理](05_两分类数据集处理.md)，了解如何在不破坏原数据的情况下生成推荐训练集。
